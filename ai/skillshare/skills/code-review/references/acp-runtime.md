# External review ACP runtime

This runtime applies to Codex, Grok, and Claude single reviews and every external loop round. Use the shared client instead of CLI prompts, CLI output envelopes, or provider-specific result schemas. ACP uses JSON-RPC control messages; it does not guarantee the model's answer format. The client validates the complete terminal answer against [the external result contract](external-review-result.schema.json).

## Prepare and run

Use Python 3.11 or later, Node.js 22 or later for the adapters, and the installed provider ACP peer. Authenticate with the provider's normal login outside the review when required. Do not read, copy, relocate, or print credentials. Preserve real provider state and do not change `HOME`, `CODEX_HOME`, or other standard host variables yourself. Provider-specific launch isolation belongs to the shared client.

The caller creates an owner-only run directory outside the repository, with a UTF-8 request file and an unused output path. Put the complete authorized frozen snapshot and reviewer instructions in that request. Use repository-relative paths and explicit content boundaries; include the manifest, base and current content, relevant diff/status, acceptance criteria, scope, and permitted round focus. A path to a host file is not snapshot content. Transfer no credentials, conversation history, previous verdicts, or unrelated files. The client appends the complete canonical external schema.

Resolve the client path relative to the installed `code-review` skill. Keep untrusted text in the request file, not command arguments. For example:

```sh
python3 "$ACP_REVIEW_CLIENT" --agent codex \
  --request "$REVIEW_REQUEST" --output "$REVIEW_OUTPUT"
```

`ACP_REVIEW_CLIENT` is `code-review/scripts/acp_review.py`. Select `--agent codex`, `--agent grok`, or `--agent claude` to match the explicitly invoked skill. Do not substitute another provider on failure. The total deadline defaults to 1,800 seconds; `--timeout-seconds` changes it. The idle deadline defaults to 300 seconds; `--idle-timeout-seconds` changes it. Each protocol setup response has a separate 90-second deadline. Poll the same running client; a tool wait limit is not the client's review deadline. Cancel the task-owned client before abandoning a call.

The client creates a fresh private empty working directory outside the target. It initializes ACP, creates one fresh session with no MCP servers, and sends exactly one text prompt. It does not resume, load, or share sessions. Metadata and authentication checks carry no review prompt. CLI binaries may bootstrap an ACP server; requests and results travel through ACP messages rather than CLI prompt or output formats.

## Provider peers

| Review agent | ACP process | Provider integration |
| --- | --- | --- |
| Codex | `codex-acp` from `@agentclientprotocol/codex-acp` | Bridges Codex App Server; the adapter bundles its own official Codex runtime by default. |
| Grok | Native `grok agent --no-leader stdio` | Uses Grok agent mode directly. |
| Claude | `claude-agent-acp` from `@agentclientprotocol/claude-agent-acp` | Bridges the official Claude Agent SDK; requires Node.js 22 or later. |

These are ACP server launch commands, not CLI review commands. The tested versions are Codex ACP 2.1.1, Claude ACP 0.87.0, and native Grok 1.0.46. Install missing adapters separately:

```sh
npm install --global @agentclientprotocol/codex-acp@2.1.1 \
  @agentclientprotocol/claude-agent-acp@0.87.0
```

The review client does not download packages, update providers, initiate a browser login, or substitute peers. Keep normal provider authentication in place. Codex retains real `HOME` and `CODEX_HOME`; the adapter can use its existing cached login. Claude retains normal home authentication while suppressing project and user settings. Grok sets its child `HOME` and `GROK_HOME` to separate private temporary directories and points `GROK_AUTH_PATH` to the original configured auth file. The caller's real `HOME` remains unchanged; the client does not read or copy the credential file. Child-home isolation is required because the native stdio [skill watcher](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/config/watcher.rs#L677) ignores discovery controls, watches vendor skills under `HOME`, and can inject an internal `skills-reload` response through its [agent channel](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/agent/app.rs#L167) when those skills change. The provider may refresh its normal login state. If authentication is missing, stop incomplete and use the provider's normal login flow outside the review.

`acp_providers.py` owns launch controls. Its child environment retains only standard execution, locale, TLS/proxy, and provider authentication variables; it removes inherited configuration and executable overrides. Codex uses read-only mode, no approvals or web search, disables shell and other host integrations, suppresses project/skill instructions, and disables discovered MCP entries from standard user and system configuration. It writes a nonempty reviewer system-instruction file in private scratch and clears ambient developer, compaction, and notification instructions. Claude supplies `tools: []`, `settingSources: []`, disabled hooks, strict empty MCP configuration, and `persistSession: false`. Grok supplies a custom profile with default tools, instructions, skill discovery, and MCP inheritance disabled; deny filters remove the declared tool and hosted searches. It also disables memory, auto-updates, shared-leader attachment, and vendor discovery. Do not bypass these controls when a provider fails.

Provider integration sources: [Codex adapter](https://github.com/agentclientprotocol/codex-acp/blob/main/README.md), [Claude adapter](https://github.com/agentclientprotocol/claude-agent-acp/blob/main/README.md), and [Grok agent mode](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/15-agent-mode.md). ACP behavior follows [initialization](https://agentclientprotocol.com/protocol/v1/initialization), [prompt turns](https://agentclientprotocol.com/protocol/v1/prompt-turn), and [stdio transport](https://agentclientprotocol.com/protocol/v1/transports), and [protocol extensibility](https://agentclientprotocol.com/protocol/v1/extensibility).

## Access and completion

The client advertises no filesystem or terminal capabilities and rejects file, terminal, permission, and tool requests. Provider launch controls also suppress ambient integrations and host tools. Codex retains an `apply_patch` tool advertisement: its read-only sandbox blocks mutation, and any tool event makes the review incomplete. Claude suppresses SDK built-in tools; the client rejects adapter-level tool requests. Grok filters out built-in tools. Denying client capabilities alone does not isolate an adapter's own tools or prevent host reads. ACP is a communication protocol, not a kernel sandbox. The authorized review surface is the supplied text snapshot. Do not grant target paths, host files, MCP servers, shell access, worker access, or approval bypasses to make a failing review proceed.

Require the prompt response's `end_turn` stop reason and exactly one complete JSON object assembled from that prompt's ACP assistant-message updates. Do not treat thought updates, progress, partial fragments, prose, Markdown fences, other sessions, or a CLI envelope as the result. Valid vendor metadata notifications whose names start with `_` are ignored under ACP extensibility; they add no answer text and do not establish completion. The client uses opaque `review-N` request IDs. Only a response for the exact active client request can establish completion. Malformed responses, duplicate responses, and unknown IDs within that namespace make the review incomplete. Well-formed responses outside the client namespace are discarded as unrelated transport metadata; their payloads never become model output or completion. This shared routing rule also excludes native internal responses such as Grok's `skills-reload`; it does not coerce IDs or accept stale answers. The client enforces JSON shape, finding fields, confidence/priority constraints, verdict/findings cardinality, and UTF-8 encoding of decoded result strings. Invalid Unicode returns incomplete before publication. A complete `clean` result has no findings; an `incomplete` result has no findings and identifies its gap. Protocol completion does not prove that the reviewer inspected every supplied block: the caller must independently assess the stated surface and findings.

Before launching the peer, the client checks the unused output path, opens a staging file in its parent directory, and verifies hard-link support. With that preflight complete, it writes an atomic external-contract JSON result, including review failures. It never replaces an existing output file. A later filesystem or output-path race fails closed and can prevent result publication; report that failure without claiming a saved result. Exit zero means a valid completed `clean` or `findings` result. Exit nonzero means incomplete, including a reviewer-declared incomplete result, authentication or setup failure, malformed output, protocol failure, rejected tool request, timeout, or adapter exit before completion. Inspect the bounded failure reason; protocol rejection diagnostics may name only the client-owned pending method and validated integer error code, never the peer's free-text message or data. Do not salvage partial output, invent findings, retry, resume, or fall back to CLI transport. A failed prompt consumes its loop round; failed preflight before a prompt makes the round incomplete without a model call. Client-generated failures state whether a review prompt was sent in `inspected_surface`, so the caller can count the attempt; reviewer-declared incomplete results keep the reviewer's own surface description.

Snapshot relevant target state immediately before and after the call. The reviewer must not mutate it. Stop on a boundary violation; reverse only the exact call delta when safe, and never blanket-restore a dirty tree. Keep the external result until independently assessed into [the canonical caller contract](review-result.schema.json).

## Scratch lifecycle

The client owns its adapter process and private working directory. It stops task-owned processes and removes its temporary state on success, failure, timeout, or cancellation. `SIGTERM`, `SIGINT`, and `SIGHUP` use the cancellation path where supported. Bounded cleanup is shielded from repeated cancellation so it can stop the owned process group and close its streams before returning an incomplete result. The caller owns request, output, and optional diagnostic files; remove them after assessment and verify removal, including failure or abandonment. Do not create logs solely for user presentation or expose raw provider diagnostics that can contain sensitive data.

Codex keeps normal local review-thread history under its real provider home; the released ACP adapter does not expose an ephemeral review-thread option. Removing client scratch does not remove that history or guarantee that the request exists only in scratch. Grok history is under its private `GROK_HOME` and is removed with scratch. Claude requests `persistSession: false` from its SDK. Preserve canonical schemas, real login and provider state, requested deliverables, pre-existing files, and unrelated work. Never delete shared directories wholesale. Retain only non-secret files needed for active continuation, with a named cleanup owner and removal point. Report retained paths or cleanup failures.
