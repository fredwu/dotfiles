# External review ACP runtime

This runtime applies to Codex, Grok, and Claude single reviews and every external loop round. Use the shared client instead of CLI prompts, CLI output envelopes, or provider-specific result schemas. ACP uses JSON-RPC control messages; it does not guarantee the model's answer format. The client validates the complete terminal answer against [the external result contract](external-review-result.schema.json).

## Reviewer tools and delegation

The complete text snapshot is the default review surface and remains useful without tools. When file inspection would improve coverage or speed, the caller can supply `--snapshot` to enable the provider's permitted read-only tools over prepared frozen files. Let the reviewer choose whether and how to use those tools. Encourage supported native workers when bounded parallel inspection or independent checking adds value; do not require tool use or an agent count. Each worker receives a distinct read-only assignment, the same scope and exclusions, and an evidence path mapping. The root reviewer joins results, resolves conflicts and coverage gaps, and owns one complete terminal answer. Workers cannot expand scope, invoke review skills, or launch another top-level external review.

| Provider | Prepared-snapshot tools | Native workers |
| --- | --- | --- |
| Codex | Native command tools under the read-only sandbox, with network disabled. | Optional native workers under the same read-only review limits. |
| Claude | `Read`, `Grep`, `Glob`, and `Agent`; no Bash, edits, web, hooks, MCP, persistence, or approval bypass. | A reviewer child restricted to `Read`, `Grep`, and `Glob`, with `omitClaudeMd`; no nested workers. |
| Grok | Curated `read_file`, `list_dir`, and `grep`; no Bash, edits, web, or Agent. | Disabled because inheritance of the required restrictions is unverified. |

Without `--snapshot`, retain text-only mode: no reviewer tools or workers. Tool events permitted by prepared-snapshot mode do not make a review incomplete. Recognized native child announcements register child sessions; their progress and evidence never become the root terminal answer. There is exactly one top-level root ACP session and prompt per review round. Supported native child sessions do not add loop rounds or permit follow-up root prompts.

The permitted tools are read-only. Prepared-file permissions and before/after content checks protect the frozen copy; they do not establish global kernel write or host-read confinement. Provider sandboxes can permit temporary or provider-state writes, and the prepared copy lives in temporary storage. Instruct the root and every worker to read only the supplied snapshot, never credentials or unrelated host data. ACP client-side reads use no-follow descriptors anchored to the original prepared entries; changed identities, permissions, sizes, or file content fail before content or access grants are returned. Do not claim a global privacy sandbox or use broader host access to fill a missing snapshot.

The caller may also delegate bounded snapshot gathering or verification of valid completed findings when useful. Validate and reconcile gathered content before launch; submit one complete request, excluding worker conversations, hypotheses, prior findings, and hidden conclusions. The caller owns authorization, source coverage, assessment, deduplication, and one normalized result. Partial or incomplete provider output supplies no findings. Loops may delegate coherent repairs and checks between sequential rounds; join them before preparing the next snapshot and preserve the canonical loop's ownership and verification rules.

## Prepare and run

Use Python 3.11 or later, Node.js 22 or later for the adapters, and the installed provider ACP peer. Authenticate with the provider's normal login outside the review when required. Do not read, copy, relocate, or print credentials. Preserve real provider state and do not change `HOME`, `CODEX_HOME`, or other standard host variables yourself. Provider-specific launch isolation belongs to the shared client.

The caller creates an owner-only run directory outside the repository, with a UTF-8 request file and an unused output path. Put the complete authorized frozen snapshot and reviewer instructions in that request. Use repository-relative paths and explicit content boundaries; include the manifest, base and current content, relevant diff/status, acceptance criteria, scope, and permitted round focus. A path to a host file is not snapshot content. Transfer no credentials, conversation history, previous verdicts, or unrelated files. The client reads the request and optional bundle from regular, non-symlink files under the existing byte bound before UTF-8 decoding. It preserves request line endings and appends the complete canonical external schema.

Resolve the client path relative to the installed `code-review` skill. Keep untrusted text in the request file, not command arguments. For example:

```sh
python3 "$ACP_REVIEW_CLIENT" --agent codex \
  --request "$REVIEW_REQUEST" --output "$REVIEW_OUTPUT"
```

For prepared file access, add `--snapshot "$REVIEW_SNAPSHOT"`. The caller creates this UTF-8 JSON file inside its owner-only run directory:

```json
{"files":[{"path":"current/src/a.py","content":"UTF8 text","sha256":"d85b215bcd209696c983da02608da21ae856177ef34163bcd524cb9aea268aea"}]}
```

Use relative paths under explicit `current/`, `base/`, and `context/` roles as needed. State the layout in the request and map each prepared path to repository-relative finding evidence; for example, `current/src/a.py` maps to `src/a.py`. This workspace is a frozen source copy, not a Git checkout or worktree; do not invent Git identity or infer repository state from it. Copy only authorized text already included in the request and manifest. Verify paths, roles, UTF-8 byte sizes, and SHA-256 hashes against the frozen request before the call; missing content or disagreement makes preparation incomplete. The client validates bundle paths and hashes, then copies content into its own private working directory without accessing original source files. Exclusive creation of each distinct directory prefix and file rejects spelling aliases on the actual filesystem; exact shared parent prefixes are created once. Conflicting directory spellings cannot change manifest evidence paths before launch. The bundle supplements the complete request; it never replaces source blocks or permits a partial review target.

`ACP_REVIEW_CLIENT` is `code-review/scripts/acp_review.py`. Select `--agent codex`, `--agent grok`, or `--agent claude` to match the explicitly invoked skill. Do not substitute another provider on failure. The total deadline defaults to 1,800 seconds; `--timeout-seconds` changes it. Protocol inactivity has no default cutoff: silent SDK inference may emit no ACP updates. `--idle-timeout-seconds` explicitly opts into a positive silence cutoff; reaching it does not prove a hang. Each protocol setup response has a separate 90-second deadline. Poll the same running client; a tool wait limit is not the client's review deadline. Cancel the task-owned client before abandoning a call.

The client creates a fresh private working directory outside the target, empty in text-only mode or populated only from the optional snapshot bundle. It initializes ACP, creates one fresh root session with no MCP servers, and sends exactly one top-level text prompt. It does not resume, load, or share sessions. Metadata and authentication checks carry no review prompt. CLI binaries may bootstrap an ACP server; requests and results travel through ACP messages rather than CLI prompt or output formats.

## Provider peers

| Review agent | ACP process | Provider integration |
| --- | --- | --- |
| Codex | `codex-acp` from `@agentclientprotocol/codex-acp` | Bridges Codex App Server; the adapter bundles its own official Codex runtime by default. |
| Grok | Native `grok agent --no-leader stdio` | Uses Grok agent mode directly. |
| Claude | `claude-agent-acp` from `@agentclientprotocol/claude-agent-acp` | Bridges the official Claude Agent SDK; requires Node.js 22 or later. |

These are ACP server launch commands, not CLI review commands. The tested versions are Codex ACP 2.1.1, Claude ACP 0.87.0, and native Grok 1.0.46. Install missing adapters separately:

```sh
npm install --global @agentclientprotocol/codex-acp@2.1.1 \
  @agentclientprotocol/claude-agent-acp@0.87.0
```

The review client does not download packages, update providers, initiate a browser login, or substitute peers. Keep normal provider authentication in place. Codex retains real `HOME` and `CODEX_HOME`; the adapter can use its existing cached login. Claude retains normal home authentication while suppressing project and user settings. Grok sets its child `HOME` and `GROK_HOME` to separate private temporary directories and points `GROK_AUTH_PATH` to the original configured auth file. The caller's real `HOME` remains unchanged; the client does not read or copy the credential file. Child-home isolation is required because the native stdio [skill watcher](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/config/watcher.rs#L677) ignores discovery controls, watches vendor skills under `HOME`, and can inject an internal `skills-reload` response through its [agent channel](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/agent/app.rs#L167) when those skills change. The provider may refresh its normal login state. If authentication is missing, stop incomplete and use the provider's normal login flow outside the review.

`acp_providers.py` owns launch controls. Its child environment retains only standard execution, locale, TLS/proxy, and provider authentication variables; it removes inherited configuration and executable overrides. Codex uses native read-only mode with no approvals, network, or web search; suppresses project/skill instructions and other host integrations; and disables discovered MCP entries from standard user and system configuration. Prepared-snapshot mode permits read-only command tools and optional native workers; text-only mode disables these. It writes a nonempty reviewer system-instruction file in private scratch and clears ambient developer, compaction, and notification instructions. Claude disables auto-memory in both modes with child-only `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, independently of filesystem settings and session persistence. This prevents automatic memory loading and creation without changing the caller environment or normal authentication. Claude also supplies `settingSources: []`, disabled hooks, strict empty MCP configuration, and `persistSession: false`; its prepared-snapshot tool list and restricted reviewer child follow the table above, while text-only mode supplies `tools: []`. Grok's profile disables default tools, instructions, skill discovery, and MCP inheritance. Prepared-snapshot mode enables only the curated file tools above, while deny filters remove other tools and hosted searches; text-only mode uses the workspace sandbox with tools disabled. It also disables memory, auto-updates, shared-leader attachment, and vendor discovery. In prepared-snapshot mode on macOS, its private sandbox profile extends built-in read-only and lists the stock socket-file denies and original caller-home Docker endpoints explicitly, avoiding automatic socket symlink-resolution failures; on other systems, prepared-snapshot mode uses built-in read-only. These file denies do not establish outbound-network or IPC isolation. Do not bypass these controls when a provider fails.

Provider integration sources: [Codex adapter](https://github.com/agentclientprotocol/codex-acp/blob/main/README.md), [Claude adapter](https://github.com/agentclientprotocol/claude-agent-acp/blob/main/README.md), and [Grok agent mode](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/15-agent-mode.md). ACP behavior follows [initialization](https://agentclientprotocol.com/protocol/v1/initialization), [prompt turns](https://agentclientprotocol.com/protocol/v1/prompt-turn), and [stdio transport](https://agentclientprotocol.com/protocol/v1/transports), and [protocol extensibility](https://agentclientprotocol.com/protocol/v1/extensibility).

## Access and completion

The prepared-snapshot prompt binds filesystem root `.` to the ACP session working directory and lists exact file and directory paths from the sealed baseline before the untrusted request. Use those bundle-relative targets; a logical repository name is a label, and source examples, hyperlinks, host paths, and filesystem `/` are not tool targets. A tool that requires an absolute path must join a listed relative path to the session working directory. This index supplements the complete unchanged source, request, and schema; it does not replace them or truncate outgoing prompts. Text-only prompts remain unchanged.

In prepared-snapshot mode, the client advertises `fs/read_text_file` and reads only regular files beneath its prepared working directory. Ordinary scoped read failures, including missing files, invalid line ranges, or ranges too large for one frame, return bounded errors so the reviewer can correct them within the same turn. For unavailable scoped read/search targets, the client selects an offered `reject_once` option without granting access. If no usable single-use refusal is offered, it cancels and returns incomplete. Read limits include the complete serialized JSON-RPC reply, including the request ID, envelope, escaping, and newline. Omitted or null start lines mean line 1. Ranges use LF line boundaries and preserve original line endings. Permission requests require a nonempty string tool-call ID. The client validates all merged concrete targets, including worker locations, before granting one-use access for existing scoped reads/searches or the restricted reviewer agent. Claude Agent/Task inputs require `subagent_type: reviewer` and a nonempty prompt; optional description/name must be nonempty strings, and `run_in_background` must be Boolean. Other roles, model, isolation, and unrelated options receive the same single-use refusal, so the root reviewer may correct its choice or inspect directly. The pinned Codex peer distinguishes continuation (`decline`) from cancellation (`cancel`); the client prefers the offered continuation and excludes cancellation. An adapter that still ends the turn after refusal cannot establish completion. Malformed call context, unsupported capabilities, symlinks, path escape, leading home-relative `~` components, writes, terminal requests, persistent grants, and elevations remain fatal. Concrete native tool `path`, `file_path`, Grok `target_file` and `target_directory`, and supported explicit `cwd` values, plus reported locations, must also stay within the prepared workspace, including early unclassified calls, child events, and merged updates. Explicit `cwd` must name an existing scoped directory; read-file permission checks apply to actual path and location targets, not that working directory. Native read notifications may report scoped missing paths, directories, or alternate spellings without granting access or returning client file bytes; the reviewer can handle an unavailable tool result and continue the same turn. Read permissions require existing regular files, while search permissions require existing targets. Direct read errors and permission refusals remain recoverable. Native source I/O failures and observed boundary violations end the review as incomplete. The protocol reader handles uncaught source or transport I/O errors with a fixed diagnosis, settles pending requests, and completes owned cleanup before saving incomplete. Mutation and programming errors retain their existing behavior. For concrete targets, an observable path escape or symlink stops the review. Search may omit `path` or report it as null or empty to use the prepared working directory. Early unclassified `other` metadata defers those same absent optional `path` values without granting read access; a later typed read still requires a concrete valid operand. Read `path`, `file_path`, `target_file`, `target_directory`, explicit `cwd`, and location paths retain their strict nonempty-string checks. Other malformed values and all concrete scope checks remain unchanged. This check does not prevent unreported native host reads or inspect command text. Tool tracking retains only permission metadata and call identifiers under a bounded total; tool content and outputs are not cached. An omitted initial tool kind defaults to `other` and does not grant permission. Omitted or null update `kind`, `name`, `rawInput`, and `locations` preserve cached values; explicit invalid kinds or location entries remain errors. In text-only mode it advertises no filesystem or terminal capabilities. Provider-native tools follow the mode-specific launch controls above; ACP capability restrictions do not independently confine native host reads. ACP is a communication protocol, not a kernel sandbox. Do not grant source-repository paths, unrelated host files, MCP servers, write tools, or approval bypasses to make a failing review proceed.

Require the root prompt response's `end_turn` stop reason and exactly one complete JSON object in the root's final assistant message. Select the latest eligible root answer. When an explicit final answer is declared, ignore explicitly marked commentary; without that declaration, terminal commentary cannot establish completion. Eligible answers must follow the last root tool event, direct file read, or permission callback; an earlier explicit final answer cannot override a later eligible unphased answer. Child activity and unrelated progress or usage updates do not advance this root boundary. Preserve message boundaries and declared answer phases; otherwise use the last root message after tool activity. Bound retained root text, message identifiers, entry metadata, and fragment bookkeeping together; empty chunks add no retained fragments, while new empty message boundaries still consume the budget. Parse the selected message in full, without extracting JSON from mixed prose. Do not treat thought updates, progress, partial fragments, prose, Markdown fences, child-session output, unrelated sessions, or a CLI envelope as the result. Valid vendor metadata notifications whose names start with `_` are ignored under ACP extensibility; they add no answer text and do not establish completion. The client uses opaque `review-N` request IDs. Only a response for the exact active client request can establish completion. Malformed responses, duplicate responses, and unknown IDs within that namespace make the review incomplete. Well-formed responses outside the client namespace are discarded as unrelated transport metadata; their payloads never become model output or completion. This shared routing rule also excludes native internal responses such as Grok's `skills-reload`; it does not coerce IDs or accept stale answers. The client enforces JSON shape, finding fields, confidence/priority constraints, verdict/findings cardinality, and UTF-8 encoding of decoded result strings. Invalid Unicode returns incomplete before publication. A complete `clean` result has no findings; an `incomplete` result has no findings and identifies its gap. Protocol completion does not prove that the reviewer inspected every supplied block: the caller must independently assess the stated surface and findings.

Before launching the peer, the client checks the unused output path, opens a staging file in its parent directory, and verifies hard-link support. With that preflight complete, it writes an atomic external-contract JSON result, including review failures. It never replaces an existing output file. A later filesystem or output-path race fails closed and can prevent result publication; report that failure without claiming a saved result. Exit zero means a valid completed `clean` or `findings` result. Exit nonzero means incomplete, including a reviewer-declared incomplete result, authentication or setup failure, malformed output, protocol failure, prohibited tool or capability request, timeout, or adapter exit before completion. Client-generated failures append bounded transport status to `residual_risk`: fixed ACP stage, timings, observed activity counts, stderr byte counts, exit observed before owned cleanup, and separate cancellation/signal actions. A lexical scope rejection also records the first fixed operation, target-field, root-or-child, and rejection-reason classes. Constructor-root spelling aliases are classified lexically for diagnosis only; the client does not resolve or remap rejected paths or change access grants. This status contains no source, prompt, argument, ID, path, raw stderr, or peer error text; it does not establish why a silent peer stalled. Initial failures before launch have no invented transport metrics, and valid reviewer results remain unchanged. Protocol rejections identify only the client-owned method and validated integer error code. Do not salvage partial output, invent findings, retry the failed call, resume its session, or fall back to CLI transport. A failed prompt consumes its loop round; failed preflight before a prompt is incomplete without consuming a model round. A standalone review returns that incomplete result. In a loop, the caller owns diagnosis, verified correction, cleanup, and the next fresh sequential attempt under the canonical [failure recovery policy](../../code-review-loop/SKILL.md#recover-failed-attempts); the client never launches it automatically. Client-generated failures state whether a review prompt was sent in `inspected_surface`, so the caller can count the attempt; reviewer-declared incomplete results keep the reviewer's own surface description.

The client pins the prepared root before one initial streamed capture, then seals the entry identities, types, complete permissions, file sizes, and hashes into an immutable baseline. The same boundary owns active access and final verification. Exact child names are derived from that baseline; anchored parent namespaces are checked before and after access, including exceptional exits and directory-only targets. An alternate case or Unicode spelling has the same unavailable-target behavior as a scoped missing path; it does not remap evidence or grant access. Actual additions, removals, renames, links, or changed entry metadata remain fatal. Active client reads and concrete target checks walk the original entries with no-follow directory descriptors and check their original metadata before and after access. Direct reads use the original prepared byte size as their hard read bound and compare full-file bytes with the original hash before returning text. An observed size breach is fatal even if the source is restored before access ends; concrete regular-file targets use the same bounded streamed hash check before native activity or access grants are accepted. Validated entry and root checks also run when an operation aborts, before descriptors close unconditionally. A recoverable error cannot hide a metadata change or a newly created target that was originally absent. Unchanged-source read errors and programming exceptions retain their normal handling. Paths absent from the original baseline remain recoverable while still absent; new or replaced entries are fatal. Directory-only or unreported native activity does not prove that all file reads were confined. Private-workspace verification checks the same original root and entry identities before access. It streams the expected entry set through anchored directory descriptors, checks directory identity before and after traversal, rejects unexpected entries or changed types, complete permission bits (including sticky, setuid, and setgid), and sizes before content access, and hashes known files through no-follow descriptors in bounded chunks. Active file reads are bounded by the prepared size even if a source grows after its size check. Snapshot relevant target state immediately before and after the call. The reviewer must not mutate it. Stop on a boundary violation; reverse only the exact call delta when safe, and never blanket-restore a dirty tree. Keep the external result until independently assessed into [the canonical caller contract](review-result.schema.json).

## Scratch lifecycle

The client owns its adapter process and private working directory. It stops task-owned processes and removes its temporary state on success, failure, timeout, or cancellation. `SIGTERM`, `SIGINT`, and `SIGHUP` use the cancellation path where supported. Bounded cleanup is shielded from repeated cancellation so it can stop the owned process group and close its streams before returning an incomplete result. The caller owns request, optional snapshot bundle, output, and optional diagnostic files; remove them after assessment and verify removal, including failure or abandonment. Do not create logs solely for user presentation or expose raw provider diagnostics that can contain sensitive data.

Codex keeps normal local review-thread history under its real provider home; the released ACP adapter does not expose an ephemeral review-thread option. Removing client scratch does not remove that history or guarantee that the request exists only in scratch. Grok history is under its private `GROK_HOME` and is removed with scratch. Claude requests `persistSession: false` from its SDK. Preserve canonical schemas, real login and provider state, requested deliverables, pre-existing files, and unrelated work. Never delete shared directories wholesale. Retain only non-secret files needed for active continuation, with a named cleanup owner and removal point. Report retained paths or cleanup failures.
